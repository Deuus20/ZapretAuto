# Как помочь проекту

Спасибо, что хотите помочь. Ниже коротко: как сообщить о проблеме, как собрать проект и что проверить перед pull request.

## Проблемы и идеи

- Сначала загляните в [решение проблем](docs/troubleshooting.md) и во вкладку «Диагностика» → «Найти проблемы».
- Для ошибки откройте issue по шаблону «Что-то не работает» и приложите отчёт: «Диагностика» → «Сохранить отчёт об ошибке…».
- Идеи и вопросы - обычный issue.
- Об уязвимостях не пишите в публичный issue, порядок в [SECURITY.md](SECURITY.md).

## Разработка

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python main.py
.venv\Scripts\python -m pytest -q
.venv\Scripts\python -m ruff check main.py app scripts tools tests
.venv\Scripts\python -m pyright
```

Тесты работают офлайн: `tests/conftest.py` блокирует сокеты, DNS и UDP, каждый тест получает временные каталоги данных. Сеть для тестов не нужна.

Сборка установщика: `powershell -File build.ps1`, нужен Inno Setup 6. Скрипт сначала гоняет тесты, потом собирает `dist\ZapretAuto`, portable zip и установщик.

## Правила кода

- Python 3.12, аннотации типов обязательны, pyright должен давать 0 ошибок.
- Новые зависимости - только если без них нельзя; runtime-версии фиксируются в `requirements.lock` с хэшами.
- Меняете поведение - добавьте тест. Тест должен падать без исправления.
- Не редактируйте `vendor/zapret`: это неизменённая сборка upstream, её перезаписывает обновление.
- Строки интерфейса на русском, документация на русском, код и комментарии можно на английском.
- Длинные тире в текстах и документации не используем.

## Pull request

- Одна тема на PR, без попутных переименований.
- Прогоните pytest, ruff и pyright; в описании укажите, что именно проверяли.
- Если меняете поведение, обновите CHANGELOG.md в разделе «Не выпущено».
- Отправляя PR, вы соглашаетесь, что вклад распространяется по MIT, см. [LICENSE](LICENSE).
